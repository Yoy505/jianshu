# GLM 开发规范（jianshu / 杏临汇）

版本：2026-09-23。适用范围：`backend/`、`miniprogram/`、`essay-h5/`、`admin-web/`、`deploy/`。这是今后开发的执行标准；既有实现是否达标以《代码质量审核与方向订正-2026-09-23.md》的证据和后续验收为准。

## 1. 每项任务先做什么

1. 先读本文件、`docs/总体开发计划-2026-09-23.md`、`README.md`、`docs/api.md`、相关代码与测试，确认当前 Git 状态。只修改本任务涉及的文件，不覆盖他人未提交的改动。
2. 用一句话写清用户可观察的目标、真实数据来源、权限边界和不在本次任务中的功能。涉及健康服务时，标明是**健康信息/服务协助**还是**互联网诊疗**；边界未确定时先做不涉及诊疗的部分。
3. 提交变更前列出接口、数据表、状态、页面、迁移和测试会受什么影响。对已有接口先改 `docs/api.md`，再改实现；不默改字段语义。
4. 不把“界面已画好”“编译通过”“演示数据可点通”写成“业务已上线”。交付说明必须写明真实服务是否已接通。

## 2. 业务真实性与医疗边界（最高优先级）

- 所有“已核验资质”“可约时段”“真人在线”“已收到申请”“短信已发送”“已完成服务”等断言，必须由服务端持久化状态或外部服务成功回执支持。无依据时只显示准确的状态，禁止用固定文案、定时器、随机数或哈希值假装成功。
- 专业人员资料应有身份、执业机构、执业范围、证照/核验结果、核验时间、有效期与审核人等受控字段；客户端只展示核验通过且有效的资料。演示人员与真实人员分开存储或明确标记，生产不得混用。
- 自动消息必须以 `automation` 等独立发送方类型记录并显式展示；不得保存为 `provider` 或代具体医师发言。真人回复要绑定实际人员身份、会话授权和可追溯时间。
- 预约展示与下单使用同一排班/容量数据源；下单在数据库事务中检查服务、人员资质、时段、容量、冲突和状态，并用约束或锁防并发超卖。没有真实排班时只能提交“预约意向”，不得宣称“已预约成功”。
- AI 仅在经过产品、医疗合规和数据处理评审后进入健康场景。不可把 AI 称为医师、代医师诊断或开具处方。危险症状、用药和急症请求需有明确转人工/就医路径；免责声明不能替代真实的服务边界。
- 健康档案按敏感个人信息处理：收集前明确目的和必要字段，取得所需的单独同意，记录同意版本，提供访问/更正/撤回/删除路径；权限最小化、传输加密、日志脱敏、导出受控、保留期可配置。跨主体共享先明确双方责任、合同、告知与授权。
- 药品信息、用户留言、商品和内容推广先区分科普、广告、交易与诊疗。用户生成的健康内容先审核再公开；处方药、特医食品等按实际经营方式完成专项审查，不能以“展示页”规避。

监管依据核对入口：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)、[互联网诊疗监管细则（试行）](https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml)、[药品网络销售监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_27f2fba302ab48239dfde1a5b5095156.html)。具体上线类目、资质和运营方式应由项目主体与专业合规人员核定。

## 3. 后端与数据

- 命名约定：Python 模块、变量和函数用 `snake_case`，类用 `PascalCase`；TypeScript/小程序变量与函数用 `camelCase`，组件/类型用 `PascalCase`。领域枚举、状态和字段名沿用 `docs/api.md`，不要在各端另造同义名称。
- 金额统一以整数“分”在接口与数据库传递，展示时才转换；时间在后端保存带时区的 UTC，客户端按用户时区展示；日期与时段按服务发生地规则计算，不能混用本地时间和 UTC。
- 路由层只负责鉴权、输入输出和调用；业务状态机放服务层；复杂查询和持久化规则集中管理。新功能不要继续把大段逻辑堆入 `backend/app/api/admin/mp.py`。现有大文件按触及区域渐进拆分，不为重构而重构。
- Python 新代码保持类型标注；Pydantic 输入字段的长度、范围、枚举与数据库约束一致。响应使用明确 DTO，禁止直接返回 ORM 或敏感字段。错误码与 `docs/api.md` 一致：输入 4xx、冲突 409、限流 429，不能把可预见的业务错误留给数据库抛 500。
- 影响多人、多端或金钱/名额的操作以数据库保证不变量；“先查询再插入”不能独自作为防重。每次表结构变更配 Alembic 迁移、回滚/兼容说明及 PostgreSQL 验证。生产不运行 `create_all`，不运行演示数据种子。
- Redis key 必须包括影响结果的全部参数和身份维度，写明 TTL 与失效策略。跨 worker 的实时消息使用共享消息通道；进程内连接表仅用于本进程发送。
- 登录、验证码、上传、咨询、投稿、后台操作按身份和来源设置合理限流。生产启动必须拒绝默认 JWT 密钥、开发后门、示例管理员口令和缺失的关键服务配置。密钥只从环境/密钥管理服务读取；依赖版本锁定并审查升级。
- 上传校验文件内容类型、尺寸和大小，避免整文件无界读入；公开媒体与私有资料分桶/目录。导出和健康资料按授权下载或短时签名链接提供，禁止把可预测文件名直接挂到公开静态路径。
- 审计记录谁、何时、对什么资源作了什么操作；记录状态变化，不记录验证码、完整健康对话或不必要的敏感信息。错误日志要有 request_id，且不包含 token、手机号全号和健康档案正文。
- 异常处理必须保留错误类型与 request_id，并完成事务回滚/资源释放；不得用空 `except`、假成功返回或固定演示值吞掉真实失败。外部服务调用应设置超时、幂等键、可观察的失败状态和有限重试。

## 4. 小程序、H5 与后台

- 页面中的承诺只来自接口真实字段。演示、待开通、申请中、核验中、预约意向等状态要明确；不可先展示成功，再等待服务端确认。
- 私有请求缓存键含当前账号 ID；登录切换、退出和封禁时清理私有缓存。异步列表使用请求代际编号或取消请求，旧响应不能覆盖新的筛选条件。WebSocket 帧按会话 ID 过滤，页面卸载/退出时断开并清理订阅。
- 不在组件里重复拼装 API 协议。统一错误、空数据、加载、重试、断网、登录过期处理；服务端仍是权限权威，前端隐藏按钮只是体验优化。
- 变更关键流程须在实际运行环境验证：小程序模拟器与真机、H5 移动浏览器、后台目标浏览器。构建成功只证明静态编译，不证明界面、实时通道、登录、支付/预约或医疗服务真实可用。
- 新页面保持现有设计系统和中文文案，适配长文本、系统字号与安全区；关键操作提供可见反馈和可恢复失败路径。

## 5. 按风险验收，而非堆测试数量

| 变更类型 | 必须留下的证据 |
|---|---|
| 文案/样式局部调整 | 目标页面实际截图或预览，确认文案准确且无遮挡 |
| API/业务规则 | 正常、失败、权限和边界用例；接口契约更新 |
| 预约、名额、点赞、会话 | 并发/重复请求测试，数据库约束与状态机测试 |
| 身份、健康数据、导出 | 越权、跨账号缓存、敏感字段泄露、审计与撤回路径测试 |
| 迁移、缓存、Celery、WebSocket | PostgreSQL/Alembic 集成测试；实际 Redis/跨 worker 或外部服务合同测试 |
| 部署/生产配置 | 测试环境冒烟、失败配置拒绝启动、备份与恢复、回滚演练 |

质量门禁逐步建立为：Python 格式和静态检查（建议 Ruff）、后端 pytest、Alembic 升级检查、PostgreSQL 集成测试；H5/后台 TypeScript 构建和 ESLint；小程序 JS/JSON 检查与关键路径自动化/实际预览。当前仓库尚未配置完整 CI 和锁定 Python 依赖，先建立基线；后续修改不得降低已建立的门禁。低风险可逆改动不必写只重复实现的测试。

## 6. 交付格式与上线闸门

每次 GLM 交付必须按此顺序说明：目标与范围；改了哪些文件和接口/迁移；实际执行的命令及结果；关键页面/流程的真实验证；未验证项与风险；是否可部署。失败或未运行的测试必须如实写出，不得用“理论上通过”替代。

任何生产发布至少满足：无默认口令/开发后门；真实登录与短信成功；用户数据与导出隔离；健康服务状态和资质信息真实；预约不超卖；咨询不冒充真人；隐私告知和授权完成；内容审核生效；关键流程实测；备份恢复、监控告警和回滚可用。医师诊疗、处方或药品交易另按实际经营方式完成机构/人员/类目审查。未过闸门的模块只能留在隔离演示环境。

## 7. 给 GLM 的首条任务指令（可直接复制）

> 请先阅读 `docs/总体开发计划-2026-09-23.md`、`docs/GLM-开发规范.md`、`docs/代码质量审核与方向订正-2026-09-23.md`、`docs/api.md` 和相关源码。先报告当前 Git 状态、你要修复的一个具体问题、真实数据来源、涉及的接口/迁移/页面及验收方案，再修改代码。优先按总体计划的 R0 和审核报告 P0/P1 顺序处理；上线前禁止保留假资质、假排班、冒充真人的自动回复、演示账号或未接通却显示成功的服务。保持现有业务和无关改动不变。完成后给出逐文件变更、实际测试与运行证据、未覆盖风险；没有运行的检查不得声称通过。
