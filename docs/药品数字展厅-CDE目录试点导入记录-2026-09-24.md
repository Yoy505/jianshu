## 本次代码和数据处理

1. `mp_drugs` 新增批准文号、规格、上市许可持有人、来源名称/URL/核验时间及发布状态；批准文号有唯一约束。迁移将原有 14 条行标记为 `demo`，新行默认 `pending`。
2. 导入脚本先校验严格字段与官方详情链接，默认只预览；`--apply` 按批准文号幂等写入。仅可更新仍处 `pending` 的基础事实，不覆盖演示、已发布或已下架内容。
3. 小程序列表和详情展示可追溯注册字段；演示资料显式标识；未提供来源的医学内容与视频模块隐藏。后台可以按发布状态筛选并查看来源。
4. C 端开发/测试环境只读取 `demo` 和 `published`，预发布/生产只读取 `published`。`pending`、`offline` 在检索、详情、收藏及留言入口均不可访问。

本地开发库 `backend/dev.db` 已升级到 Alembic `b17e4c8d2a90`，导入后为 **14 条演示资料 + 3 条待审核官方目录记录**。当前本地 8000 端口已运行新后端代码。对该服务核验：C 端列表仍为 14 条演示资料、直接访问待审核 ID 返回 404、后台以 `publication_status=pending` 查询到 3 条。隔离数据库重复执行导入返回 3 条 `unchanged`；以预发布配置运行同一隔离库时，公开列表返回 0 条。未对生产数据库执行写入。

## 复现与发布闸门

在 `backend/` 设置目标 `DATABASE_URL` 与 `APP_ENV` 后，先核对数据库备份与迁移计划，再执行：

```sh
.venv/bin/alembic upgrade head
.venv/bin/python scripts/import_official_drugs.py
.venv/bin/python scripts/import_official_drugs.py --apply
```

本次本地开发库升级前的备份在 `/tmp/jianshu-dev-before-cde-20260924.db`；它是临时备份，不能代替部署环境的持久备份。

面向公众发布前仍需完成：资料使用依据确认、批准文号及当前状态复核、独立医学/内容审核与发布分权、来源失效/下架机制、目标 PostgreSQL 迁移及回滚验证。当前代码没有审核/发布写接口或不可变版本快照，不应通过直接修改数据库状态绕过流程。详见 [药品数字展厅首期契约](药品数字展厅-首期需求与数据契约.md)。
